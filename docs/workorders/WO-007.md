# WO-007: 右文脈 generic 補間 + GEN_W の CLI 化(snpylm)

Status: closed (merged into dev)

担当: impl-core(opus) / ブランチ: fix/WO-007
対象: tg/include/snpylm.h, tg/src/snpylm.cc, tg/src/sne.cc, tests/

## 背景

WO-006 の generic NE slot backoff(commit 94730c7)は **左文脈側**のみ:
P(NE_k|ctx) を class 別と _bg_gen の P(NE_generic|ctx) で log-mix している。
識別の残り半分は **exit フレーム**(「◯◯**氏が**」の氏が側)= P(v_{j+1}|…,NE_k)。
これを generic 側にプールして precision を回復するのが本 WO。
実験結果: v11(bypass のみ) span F .228 / V .062、v12(+左側 backoff) span F .208 / V .128。
右側補間で span precision を v11 水準へ戻しつつ V の利得を保持するのが狙い。

## 設計(司令塔確定 — 変更禁止。矛盾を発見したら停止して報告)

### 1. _bg_gen の再定義: generic 置換ストリームの的絞り台帳

記法: tvid[j] = 現行のテンプレートトークン id(_tvid)。
gvid[j] = (s.ch(j).k >= 1) ? _ne_generic : tvid[j](generic 置換 id)。

_add_remove_bg(または相当箇所、snpylm.cc:589 付近)の _generic_backoff 分岐を変更:

- **(a) NE 位置 j**: 従来どおり `_bg_gen->add(_ne_generic, hg)`。ただし文脈キーを
  `pid = tvid[j-d]` から `pid = gvid[j-d]` に変更(連続 NE で先行 NE も generic 化)。
- **(b) 追加: 直前 n-1 窓に NE を含む位置 j(単語)**: トークン `tv`(id=tvid[j],
  _bg への着席と同じ chunk)を gvid 文脈で `_bg_gen->add(tv, hg)`。
  条件: ∃d∈[1,n-1]: j-d>=0 かつ s.ch(j-d).k>=1。
- **(c) 追加: EOS**: 末尾 n-1 窓(位置 M-1..M-(n-1))に NE を含む場合、
  eos chunk(id 0)を gvid 文脈で _bg_gen に着席。
- remove 側は完全対称(find が NULL なら throw、既存パターン踏襲)。

### 2. 予測: _trans_lp の右側混合

シグネチャ拡張: `_trans_lp(chunk& ch, int k, const context *c, const context *cg, bool ctx_has_ne)`。

- k >= 1: 従来式のまま(gen 項の cg が generic キー文脈になるだけ)。
  `log( w·P_bg(NE_k|ctx) + (1-w)·P_gen(NE_generic|gctx) · rho_k )`
- k == 0(単語)/ EOS: `ctx_has_ne == true` のときのみ
  `log( w·P_bg(v|ctx) + (1-w)·P_gen(v|gctx) )`(rho_k は掛けない)。
  false なら従来どおり base のみ(NE 無関係領域のスコアは不変 — 回帰防止)。
- w は新メンバ _gen_w(下記 3)。
- deficiency コメント必須: 混合は窓に NE を含む遷移のみに適用され生成モデルとして
  正規化しないが、着席台帳は対称なので consistent なサンプラースコア
  (l1 bypass と同じ論法。snpylm.cc:700 のコメント参照)。

### 3. 格子スレッディング(_forward / _backward / _slice)

- _forward/_backward(snpylm.cc:829, 850)の再帰で:
  - `hg` の find キーを `sig` から `gsig = (sig が NE シンボル) ? _ne_generic : sig` に変更。
    NE シンボル判定は `_nek` の逆引き(既存の _sigma 実装参照。id 比較で O(k) になるなら
    NE シンボル id の範囲/セットを保持して O(1) に)。
  - `ctx_has_ne` を bool 引数として再帰に流し(初期 false、NE シンボルを踏んだら true)、
    n<=1 の底で _trans_lp に渡す。
- _slice 内の直接呼び出し(snpylm.cc:785 `_trans_lp(c, k, _bg->h(), _bg_gen->h())`)は
  ルート文脈(履歴周辺化なし)なので ctx_has_ne=false を渡す(現行スコアと同値、変更なし)。
- EOS 遷移の呼び出し元も ctx_has_ne を正しく渡すこと。

### 4. GEN_W の CLI 化

- `#define GEN_W 0.5`(snpylm.cc:23)を削除し、メンバ `double _gen_w`(既定 0.5)に。
- setter `set_gen_w(double)`(0 < w < 1 を検証、範囲外は throw)。
- sne.cc に `--gen_w F` を追加(usage 文言も)。--no_generic_backoff との関係は現状維持。
- serialize: save/load に _gen_w を追加。**フォーマット互換**:
  - 既存の generic ブロック(snpylm.cc:1162 付近)はマーカー方式のはず。旧形式
    (WO-006 の tvid キー _bg_gen)は台帳の意味が変わったため **backoff off + 空 _bg_gen
    で load**(cerr に一行警告)。新形式マーカーを更新して新旧を判別すること。
  - legacy(generic ブロックなし)は従来どおり off。
